WF-01 用户登录工作流

测试目标

验证用户能够正常登录系统，并根据账号权限显示对应菜单。

前置条件

1. 系统服务正常。
2. 已创建可用用户。
3. 用户已配置角色和菜单权限。

操作步骤

1. 打开MES登录页面。
2. 输入正确用户名。
3. 输入正确密码。
4. 输入正确验证码计算结果。
5. 点击“登录”。

预期结果

1. 登录成功。
2. 跳转至MES首页。
3. 页面显示当前登录用户名。
4. 用户只能看到已授权菜单。
5. 系统记录登录日志。

异常分支

1. 用户名错误，提示账号或密码错误。
2. 密码错误，不允许登录。
3. 验证码错误，不允许登录。
4. 停用用户不允许登录。
5. 无角色用户登录后，不应看到未授权菜单。
6. 连续多次输错密码后的处理符合系统规则。

一、基础数据测试工作流

WF-02 创建车间工作流

测试目标

验证车间基础数据能够正常新增，并为设备、产品和生产工单提供引用。

前置条件

1. 用户已登录。
2. 用户拥有车间设置权限。
3. 已配置车间编号规则，或允许手工输入编号。

操作步骤

1. 进入【基础数据】。
2. 点击【车间设置】。
3. 点击“新增”。
4. 输入车间名称。
5. 车间编码保持为空。
6. 保存。

预期结果

1. 车间保存成功。
2. 系统自动生成唯一车间编码。
3. 新车间出现在车间列表。
4. 可以按车间名称和编码查询。
5. 其他需要选择车间的表单可以选择该车间。

异常分支

1. 车间名称为空，不允许保存。
2. 手工输入重复车间编码，不允许保存。
3. 编号规则不存在时，应给出明确提示。
4. 已被设备或生产数据引用的车间删除时，应阻止删除或提示引用关系。
5. 停用车间后，新业务不应继续选择该车间。

WF-05 创建工艺路线工作流

测试目标

验证工艺路线可以关联多个工序，并能够保存工序顺序。

前置条件

1. 已创建至少3个工序。
2. 用户拥有工艺路线维护权限。

操作步骤

1. 进入【基础数据】。
2. 点击【工艺路线】。
3. 点击“新增”。
4. 输入工艺路线名称。
5. 添加工序A。
6. 添加工序B。
7. 添加工序C。
8. 将工序C拖动到工序B之前。
9. 保存。
10. 刷新页面。
11. 重新打开该工艺路线。

预期结果

1. 工艺路线保存成功。
2. 工序顺序按拖拽后的顺序保存。
3. 刷新后工序顺序不变。
4. 工艺路线列表显示正确。
5. 产品定义中可以选择该工艺路线。

异常分支

1. 工艺路线名称为空。
2. 工艺路线中未添加任何工序。
3. 同一工序重复添加。
4. 已生成生产工单后修改工艺路线，历史工单任务不应被错误改变。
5. 多人同时编辑同一路线时，应避免互相覆盖。
6. 拖拽后未保存，刷新后应恢复原顺序。

WF-37 自定义编号并发工作流

十、建议测试部门优先自动化的核心流程

测试部门可以先按以下顺序建立自动化脚本。

P0核心主流程

流程A：销售订单到生产完成

创建基础数据
→ 创建产品
→ 创建BOM
→ 创建销售订单
→ 生成生产工单
→ 工单拆分任务
→ 分批报工
→ 审批通过
→ 检查任务进度
→ 检查工单进度
→ 检查库存扣料
→ 检查生产产出

流程B：生产完成到销售出库

生产报工完成
→ 过程检验
→ 成品入库
→ 出货检验
→ 销售出库
→ 检查库存余额
→ 检查库存收发明细

流程C：报工异常处理

创建报工单
→ 提交审批
→ 审批驳回
→ 修改报工
→ 重新提交
→ 审批通过
→ 作废报工
→ 检查进度回退
→ 检查库存回冲

流程D：库存不足

准备不足的原材料库存
→ 创建生产报工
→ 审批报工
→ 系统阻止或按配置处理
→ 验证库存、任务和工单事务一致

流程E：质量不合格

创建过程检验
→ 填写不合格结果
→ 提交
→ 尝试继续报工
→ 尝试完成工单
→ 尝试入库或出库
→ 验证系统质量控制规则

十一、每条自动化用例必须检查的内容

测试脚本不要只判断“操作成功”，每个流程至少检查以下内容：

1. 页面是否提示成功。
2. 单据状态是否正确。
3. 工单和任务关联是否正确。
4. 数量累计是否正确。
5. 任务进度是否正确。
6. 工单进度是否正确。
7. 库存余额是否正确。
8. 库存收发明细是否生成。
9. 审批记录是否生成。
10. 操作日志是否生成。
11. 重复提交是否幂等。
12. 作废后是否正确回冲。

例如报工审批通过后，自动化脚本应一次检查：

报工单状态 = 已审批
任务累计数量 = 原数量 + 本次报工数量
任务进度 = 正确
工单进度 = 正确
原材料库存 = 正确扣减
半成品或成品库存 = 正确增加
库存收发明细 = 已生成
审批记录 = 已生成
