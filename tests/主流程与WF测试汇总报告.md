## 修复记录

### 字典明细服务循环依赖

**测试点和业务流**

创建字典主表和明细 → 明细分页查询 → 修改、新增、删除明细 → 校验重复数据 → 删除主表并验证级联清理。

**通过的**

修复后，字典主从完整流程和 50 并发、200 次通知列表读取均通过。

**不通过的**

`Sys_DictionaryListService` 构造函数注入自身的 `ISys_DictionaryListService`，Autofac 形成循环依赖，`Sys_DictionaryList/GetPageData` 返回 HTTP 500。

**修复后通过的**

删除未使用的自引用字段、构造参数和赋值，保留实际使用的仓储和 `IHttpContextAccessor` 依赖。

**最后的回归测试结果**

通用回归 4/4 通过；测试夹具无残留。

### 超库存销售出库保护

**测试点和业务流**

成品入库 → 正常销售出库 → 尝试超出实时库存的销售出库 → 查询余额和收发明细。

**通过的**

正常出库、库存余额和两条收发明细均正确。

**不通过的**

首次测试中，超库存出库单能够保存。

**修复后通过的**

在 `Ware_OutWareHouseBillService` 中按出库数量和实时库存校验，库存不足时拒绝保存。

**最后的回归测试结果**

销售订单到入库链路通过，超库存单据被拒绝。

### 导出操作审计日志

**测试点和业务流**

创建受限角色 → 分别授予 `Search`、`Add`、`Update`、`Delete`、`Export` → 执行通知新增、修改、导出和删除 → 查询 `Sys_Log`。

**通过的**

目录、菜单、按钮和直接接口调用均按角色授权生效；`Add`、`Edit`、`Del` 日志存在。

**不通过的**

首次执行导出返回 HTTP 200，但没有 `LogType=Export` 日志。失败证据：`authorization-regression-20260717082522.json`。

**修复后通过的**

在通用 API 导出入口写入 `LoggerType.Export` 日志，并追加 `Export` 枚举值以保持既有日志值不变。

**最后的回归测试结果**

`authorization-regression-20260717082719.json`：12 项通过、0 项失败，`Add/Edit/Export/Del` 各 1 条审计日志。
