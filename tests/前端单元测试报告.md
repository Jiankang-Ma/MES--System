# 前端单元测试报告

## iMES.Vue3 公共层单元测试计划：前端公共基线

### 本次范围

本轮先研究并规划 PC 前端公共层单元测试，范围限定在 `源码/iMES.Vue3` 下列目录：

| 范围 | 路径 | 说明 |
| --- | --- | --- |
| 工具函数 | `src/uitils` | 日期、校验、URL、图片、树形结构等公共方法 |
| API 封装 | `src/api` | `http.js`、`permission.js`、`useTest.js` |
| 状态管理 | `src/store/index.js` | 用户信息、Token、权限、Loading 状态 |
| 路由 | `src/router` | 静态路由、动态页面路由、路由守卫、错误跳转 |

阶段一测试仍按后端统一基线约束执行：不连接 SQL Server、不连接 Redis、不调用真实 HTTP API、不修改业务规则。涉及 `axios`、`vue-router`、`element-plus`、`localStorage`、`window`、`document`、`XMLHttpRequest` 的行为通过单元测试 mock 或 jsdom 环境验证。

### 测试前缺口与建议

| 编号 | 缺口 | 建议 |
| --- | --- | --- |
| FE-BLOCK-01 | 本地 `源码/iMES.Vue3/node_modules` 不存在 | 正式执行前在 `源码/iMES.Vue3` 执行 `npm ci`；如网络受限，需要使用已有 npm 缓存或镜像 |
| FE-BLOCK-02 | 默认 `example.spec.js` 无法成立 | 用公共层真实测试替换该样例，或删除样例文件 |
| FE-BLOCK-03 | `api/http.js` 和 `api/permission.js` 需要 mock `axios`、`vue-router`、`element-plus` | 优先用现有 Mocha/Chai 手写 stub；如果覆盖成本过高，再评估新增 `sinon` 或 `axios-mock-adapter` |
| FE-BLOCK-04 | `dateFormatUtil.js` 在模块导入时读取当前日期 | 日期范围测试需要可控当前时间；可以用固定输入优先覆盖 `formatTimeStamp()`，范围函数作为第二批 |
| FE-BLOCK-05 | `http.js` 会修改 axios 全局状态 | 每个用例需重置 `axios.defaults` 和拦截器，避免串扰 |

### 第一批落地顺序

1. 清理或替换默认 `example.spec.js`，确保测试入口不被不存在组件阻塞。
2. 先写 `uitils/common.js` 和 `uitils/dateFormatUtil.js` 的纯函数测试。
3. 写 `store/index.js` 测试，重点覆盖用户缓存、Token、权限重复累积和 Loading。
4. 写 `router` 路由表和守卫测试，先不挂载真实页面组件。
5. 最后写 `api/permission.js` 和 `api/http.js`，根据 mock 难度决定是否补充测试依赖。

### 交接结论

前端公共层可以按现有 Vue CLI Mocha/Chai 测试栈推进，但正式执行前有两个硬性前置：安装前端依赖，以及替换引用不存在组件的默认样例测试。当前阶段尚未执行单元测试，以上问题均为测试计划和源码阅读结果；正式跑测后需要在本报告中补充实际通过数、失败数、修改记录和复测结果。
