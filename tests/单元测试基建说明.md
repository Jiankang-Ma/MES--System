# 单元测试基建说明

## 本轮目标与节奏（7.20～7.31）

工作方式：**单元测试 → 不改变既有业务规则的缺陷修复 → 复测 → 回归测试**。

当前阶段优先建立同一测试基线，而不是多人同时修改业务逻辑。

### 阶段一：统一基线（DDL：7 月 25 日 18:00）

1. 每位成员先从 `main` 拉取本次基线代码，并记录测试时的 commit SHA。
2. 先编写和执行自己领域的单元测试；测试代码和结果文档必须一起提交。
3. 将分支推送到远端仓库，供全员查看和复现。推荐分支名：`test/system-permission`、`test/production`、`test/warehouse`、`test/custom-regression`。
4. **7 月 25 日前不修改业务规则。**若测试发现问题，只记录失败现象、最小复现和影响；由组长确认后进入第二阶段。

这样所有成员测试的是同一份基线代码，避免一个人的修复改变另一个人的预期或导致结果不可比。

### 阶段二：修复与回归（7 月 26 日～7 月 31 日）

经确认后可修复不改变业务规则的缺陷。每个修复必须先有失败测试，再提交修复，并完成本领域单元测试和相关 `.mjs` 回归。

## 已建立内容

- 测试工程：`源码/iMES.Net/iMES.Core.Tests`
- 框架：xUnit + Microsoft.NET.Test.Sdk + Coverlet collector
- 运行时：沿用项目的 `.NET Core 3.1`，通过 Docker SDK 镜像运行，不依赖宿主机安装 `dotnet`
- 第一批测试：通知输入契约、公共响应、角色超级管理员判定、权限/审计枚举、`SaveModel` 明细变更判定

## 运行命令

在仓库根目录执行：

```bash
docker build \
  -t imes-core-tests:local \
  -f 源码/iMES.Net/iMES.Core.Tests/Dockerfile \
  源码/iMES.Net
```

该 Dockerfile 自行还原 NuGet 包并运行测试；Docker 层会缓存还原结果。它不需要本机安装 `dotnet`，也不连接 SQL Server、Redis 或 API 容器。

## 当前验证结果

2026-07-20 已用上述命令完成首次构建：**15 个测试通过，0 个失败**。首次构建会还原 NuGet 包；后续构建复用缓存。

详细结果见 [单元测试报告.md](./单元测试报告.md)。

## 统一交付标准

每个成员在 7 月 25 日前必须提交以下内容：

- 测试工程、测试源文件和可重复执行的 Docker 命令；
- `tests/unit-results/20260725-成员-领域.md` 结果文档，记录基线 commit SHA、执行命令、通过/失败数量、失败用例和证据；
- 每个重要函数至少一条成功、边界、失败路径测试；
- `git push` 到个人测试分支；推送后在任务群/PR 中附上 commit SHA 和结果文档路径；
- 失败用例不得为“测试通过而跳过”；必须明确标注为失败、阻塞或待产品确认。

组长在 7 月 25 日统一核对各分支的基线 SHA 和测试结果。确认基线后，才允许开始修复；修复 PR 必须包含“失败测试 → 修复 → 复测 → `.mjs` 回归”的证据。

## 团队约定

- 单元测试文件命名：`被测类型Tests.cs`；方法命名：`场景_预期结果`。
- 每个重要函数至少覆盖成功、边界、失败三条路径。
- 不在单元测试中连接 SQL Server、Redis 或调用 HTTP；这些留给现有 `.mjs` 集成回归或后续集成测试工程。
- 修复缺陷时，先补能失败的回归测试，再提交修复代码。
- 新领域成员可复制 `iMES.Core.Tests` 的 PackageReference，分别建立 `iMES.Production.Tests`、`iMES.Warehouse.Tests` 等项目。

### 当前 Core 边界

- `ServiceBase` 的空明细数组判定已由 `SaveModelExtensions.HasDetailChanges` 覆盖；单表更新提交 `detailData: []`、`delKeys: []` 不再错误进入主从表校验。
- `ActionPermissionFilter` 依赖 HTTP Context、DI、用户缓存和角色授权数据，属于“单元夹具 + 集成验证”的边界。其真实授权行为继续由 `run-authorization-regression.mjs` 覆盖；系统权限成员后续在该基建上补充 Filter 的 HTTP Context 单元夹具。
