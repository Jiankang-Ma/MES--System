MES 系统 Critical 漏洞低影响修复过程报告 version 1.2
截止日期：2026-07-22

一、修复原则

本次只处理“不影响现有测试和业务功能”的 Critical 项：
1. 不执行 npm audit fix --force。
2. 不升级 Vue CLI 4 到 Vue CLI 5，不迁移 webpack 4 到 webpack 5。
3. 不迁移 .NET Core 3.1 到新 LTS，不做后端运行时大版本升级。
4. 不改业务源码、不改接口行为、不改前端 axios/wangeditor/sortable.js 等生产依赖大版本。
5. 使用 package-lock 级别、semver 范围内的开发依赖补丁。

二、可修复性判断

| 类别 | Critical 情况 | 是否本次修复 | 原因 |
|---|---|---|---|
| npm 生产依赖 | 修复前生产依赖 Critical 为 0 | 不需要 | 生产依赖没有 Critical；剩余为 High/Moderate，涉及 axios、wangeditor、sortable.js 等，需要专项回归 |
| npm 开发依赖 | 修复前全部依赖 Critical 为 14 | 部分修复 | 可通过 npm 6 在 lockfile v1 内升级部分传递依赖，不改变业务代码 |
| Vue CLI / webpack 开发链 | 剩余 Critical 挂在 @vue/cli-service、webpack-bundle-analyzer、html-webpack-plugin、request 等旧链路 | 暂不修复 | 继续修复需要 Vue CLI 5 / webpack 5 或破坏性依赖升级，可能影响测试 |
| NuGet / .NET | System.Drawing.Common、System.Text.Encodings.Web 等 Critical 为 netcoreapp3.1 传递依赖风险 | 暂不修复 | 低影响补丁需 NuGet 恢复和兼容验证；.NET 3.1 EOL 的根因需要 LTS 迁移 |

三、执行过程

1. 确认项目前端使用 `package-lock.json` v1，Dockerfile 使用 `node:14-bullseye` 执行 `npm ci`。
2. 本机 npm registry 原配置为 `https://registry.npm.taobao.org`，证书过期导致首次命令失败。
3. 使用一次性环境变量强制本次命令走官方 npm registry，未修改全局 npm 配置。
4. 使用 `npm@6.14.18` 执行 lockfile 级别修复，避免 npm 11 将 lockfile 升级到 v3。
5. npm 自动调整过 `less`、`stylus` 的声明版本；已恢复 `package.json` 原范围，仅保留 lockfile 中可兼容版本。
6. 重新同步 `package-lock.json`，保持 lockfileVersion=1。

六、剩余 Critical 说明

修复后全部依赖剩余 Critical：
- `@vue/cli-service`
- `ejs`
- `elliptic`
- `form-data`
- `html-webpack-plugin`
- `loader-utils`
- `request`
- `webpack-bundle-analyzer`

这些 Critical 主要属于 Vue CLI 4 / webpack 4 开发构建链。继续清零需要破坏性升级，例如 Vue CLI 5、webpack 5、替换 request 链路或迁移构建工具。由于这些动作可能影响测试环境和构建行为，本次未执行。

七、结论

本次在不改业务源码、不升级框架大版本、不执行强制修复的前提下，成功降低前端开发依赖 Critical 数量：
- Critical：14 -> 8
- 总漏洞：148 -> 119
- 生产依赖 Critical：保持 0

验证结果表明前端生产构建可通过。因此本次 `package-lock.json` 低影响修复可标记为 Remediated；剩余 Critical 需作为构建链升级专项处理，不能在“不影响测试”的前提下继续强行修复。
