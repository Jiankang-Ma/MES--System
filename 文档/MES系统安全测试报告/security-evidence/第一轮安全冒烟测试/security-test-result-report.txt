三、关键发现与判定
------------------
- [高风险] 匿名接口暴露：打印模板资源接口返回 200，日志测试接口返回 200；其中打印模板接口可匿名返回业务字段元数据，Sys_Log/test 可匿名触发测试日志写入。
- [通过] 基础鉴权：匿名访问当前用户信息返回 401，未返回当前用户业务数据。
- [通过] 普通用户访问管理员接口：普通用户调用超级管理员改密接口返回 401；管理员对照请求返回 200 并进入业务校验。
- [通过] IDOR / 水平越权：普通用户查询管理员 User_Id=1 返回 401；管理员对照查询返回 200。
- [待复测] SQL 注入初步验证：两个只读扰动请求均返回 200，未观察到 SQL 异常或堆栈泄露（report=未发现异常文本，workOrder=未发现异常文本）；但 workOrderId 非纯数字 payload 未被直接拒绝，建议补充强类型校验与专项复测。
- [通过/待关注] XSS 初测：脚本 payload 查询返回 200，响应摘录中未出现反射 payload；源码证据中仍需人工复核 v-html/innerHTML/WangEditor 使用点。
- [通过] 文件上传边界：匿名上传 HTML 返回 401，普通用户上传 HTML 返回 401，本轮未形成可访问上传文件。
- [中风险] CORS 策略：恶意 Origin 预检返回 204，Access-Control-Allow-Origin=*；Swagger 恶意 Origin GET 返回 200。生产环境建议改为明确白名单。
- [低风险] 错误信息处理：匿名 invalid Guid 返回 500，本轮未见详细堆栈；建议统一返回 400/业务错误码，避免匿名用户触发 500。

四、整改建议
------------
1. 需重点关注匿名接口：打印模板相关接口、Sys_Log/test、Swagger 暴露。
2. 普通用户访问超级管理员接口应返回无权限；若响应进入“用户不存在”等业务逻辑，说明权限控制存在缺陷。
3. IDOR 测试以普通用户查询 User_Id=1 为核心；若返回管理员记录，判定存在越权读取风险。
4. SQL 注入初步测试只做只读参数扰动；若出现 SQL 错误、堆栈或异常详情，需要进入专项 SQL 注入复测。
5. XSS 初步测试关注响应反射和源码中的 v-html/innerHTML/WangEditor 使用点。
6. 文件上传测试使用无害 HTML 文件；若匿名或普通用户可上传，需继续检查文件类型校验、公开访问和下载鉴权。
7. CORS 测试如对 https://evil.example 返回 Access-Control-Allow-Origin: * 或原样回显，生产环境需立即收紧。
8. 错误信息泄露测试如响应包含 .NET 异常类型、堆栈、SQL 语句、文件路径，应关闭详细错误并统一错误响应。
